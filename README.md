# AUMA File Manager

Веб-файловый менеджер: загрузка, скачивание, переименование, перемещение и
удаление файлов через браузер. Работает в Docker, подходит для развёртывания на
VPS.

## Возможности

- **Просмотр** — листинг каталогов, «хлебные крошки», размер, дата изменения,
  иконки по типу файла
- **Загрузка** — drag & drop в окно браузера, несколько файлов сразу, прогресс-бар
- **Скачивание** — отдельный файл или несколько выбранных одним ZIP-архивом
- **Управление** — создание папок, переименование, перемещение, удаление
  (в том числе рекурсивное для папок)
- **Предпросмотр** — картинки, PDF, текстовые файлы прямо в интерфейсе
- **Поиск** — рекурсивный поиск по имени внутри текущего каталога
- **Авторизация** — вход по логину и паролю, сессия в httpOnly-cookie
- **Безопасность** — защита от path traversal, лимит размера, квота, аудит
  действий, непривилегированный пользователь в контейнере

## Стек

| Слой | Технология |
|---|---|
| Backend | Python 3.12, FastAPI, Uvicorn |
| Хранилище метаданных | SQLite (стандартный `sqlite3`, пароли — scrypt) |
| Frontend | React 18, Vite 6 |
| Прокси и TLS | Caddy 2 (автоматический Let's Encrypt) |
| Упаковка | Docker, Docker Compose |

## Быстрый старт

```bash
# 1. Клонировать репозиторий
git clone git@github.com:ig110285-web/auma-project2.git
cd auma-project2

# 2. Создать конфигурацию
cp .env.example .env

# 3. Задать пароль администратора и секрет
#    Откройте .env и измените ADMIN_PASSWORD и SECRET_KEY.
#    Секрет удобно сгенерировать так:
openssl rand -hex 32

# 4. Запустить
docker compose up -d --build

# 5. Открыть в браузере
#    http://localhost:8080
```

При первом запуске создаётся администратор из `ADMIN_USERNAME` и
`ADMIN_PASSWORD`. Если `ADMIN_PASSWORD` не задан, пароль будет сгенерирован и
выведен в лог — смотрите его командой `docker compose logs filemanager`.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ADMIN_USERNAME` | `admin` | Логин администратора при первом запуске |
| `ADMIN_PASSWORD` | — | Пароль администратора. **Обязательно смените** |
| `SECRET_KEY` | `change-me…` | Секрет приложения. Смените на случайную строку |
| `STORAGE_ROOT` | `/data` | Корень хранилища внутри контейнера |
| `DATA_DIR` | `/app-data` | Каталог базы данных и сессий |
| `MAX_UPLOAD_MB` | `2048` | Максимальный размер одного файла, МБ |
| `DEFAULT_QUOTA_GB` | `0` | Квота на хранилище, ГБ. `0` — без ограничения |
| `ALLOW_REGISTRATION` | `false` | Разрешить самостоятельную регистрацию |
| `SESSION_TTL_HOURS` | `168` | Время жизни сессии, часы |
| `APP_PORT` | `8080` | Порт приложения на хосте (только localhost) |
| `TRUST_PROXY` | `true` | Доверять заголовкам `X-Forwarded-*` |

## Запуск с HTTPS

1. Направьте A-запись домена на IP сервера.
2. В `Caddyfile` замените `files.example.com` на свой домен.
3. Запустите вместе с профилем `proxy`:

```bash
docker compose --profile proxy up -d --build
```

Caddy сам получит сертификат Let's Encrypt. Порты 80 и 443 должны быть
свободны, а DNS — уже указывать на этот сервер.

## Разработка

Backend и фронтенд можно запускать отдельно, с горячей перезагрузкой.

```bash
# Backend
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
STORAGE_ROOT=./data DATA_DIR=./app-data ADMIN_PASSWORD=devpassword123 \
  uvicorn app.main:app --reload --port 8000

# Frontend (в другом терминале)
cd frontend
npm install
npm run dev        # http://localhost:5173, /api проксируется на :8000
```

## Тесты

```bash
cd backend
pip install -r requirements.txt -r requirements-dev.txt
pytest -q
```

Покрыты ключевые сценарии безопасности: обход каталога (`../`), абсолютные
пути, лимит размера, требование авторизации, полный жизненный цикл файла.

## Безопасность

Что уже учтено:

- **Path traversal.** Любой клиентский путь нормализуется и проверяется на
  принадлежность корню хранилища; символические ссылки наружу игнорируются.
- **Пароли.** Хранятся как scrypt-хеши со случайной солью, сравнение — с
  постоянным временем.
- **Сессии.** Токен в httpOnly-cookie, недоступен из JavaScript; после смены
  пароля все сессии пользователя разлогиниваются.
- **Загрузка.** Потоковая запись во временный файл с последующей атомарной
  подстановкой; превышение лимита или квоты откатывает запись.
- **Контейнер.** Работает под непривилегированным пользователем, с
  `no-new-privileges`.
- **Заголовки.** `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, HSTS на уровне прокси.

Что стоит сделать перед публикацией в интернет:

- Сменить `ADMIN_PASSWORD` и `SECRET_KEY` на стойкие значения.
- Включить HTTPS (профиль `proxy`) — без него пароль идёт по сети открытым
  текстом.
- В `routes_auth.py` выставить `secure=True` для cookie, когда работа идёт
  строго по HTTPS.
- Настроить резервное копирование томов `files-data` и `app-data`.
- Ограничить доступ по IP или добавить rate limiting на `/api/auth/login`.
